Method

How the detector was built, what it can tell you, and what it cannot.

What counts as drift

No public dataset pairs firewall rule-bases with the traffic they let through, so drift is detected through its symptom. A correctly maintained firewall should deny reconnaissance, exploits, denial-of-service and other malicious flows. When that traffic is seen on the network, the effective rules have moved away from the intended policy: a rule is too broad, an exception was never closed, or a port was opened by mistake.

Every UNSW-NB15 flow labelled as an attack is therefore treated as a drift-indicative flow, and every normal flow as policy-conformant. The model tells you a flow should have been blocked. Finding the rule that let it through still needs the firewall log.

Data

UNSW-NB15 training set: 175,341 flows, 45 columns, nine attack categories, 68% attack traffic. The row id and attack category were removed, leaving 42 input features. Protocol, service and state were label-encoded, all features standardised, and the data split 80/20 with stratification (140,272 training, 35,069 test).

Model

A Random Forest of 200 trees, tuned with RandomizedSearchCV (20 combinations, 3-fold cross-validation): min_samples_split=5, max_depth=None, class_weight='balanced'. Class imbalance is handled by cost-sensitive weights rather than synthetic oversampling; both gave the same F1.

Explanations

Every score comes with a SHAP breakdown: how much each feature pushed that flow toward drift or toward normal. On the Detect page a single flow is explained with exact Tree SHAP. For uploaded files the site uses the fast approximate version (Saabas), which follows the same tree paths but needs a fraction of the time, so files with thousands of flows stay quick. Exact SHAP on a 200-tree forest takes about a second per flow.

Limits

  • The model was trained offline. Traffic changes over time, so it needs periodic retraining.
  • It expects flow-level features. Raw packet captures must first go through a flow exporter such as CICFlowMeter or Argus; scoring single packets directly is not reliable.
  • At the 0.50 threshold about 7% of normal flows are flagged. The tiers help by sending only Critical flows for immediate action.
  • A flagged flow does not name the rule at fault.

Paper

Varshitha B A, Advith Rai, Krithi G Rao and Hridya Harindran K, “Firewall Rule Drift Detection Using a Hybrid Semi-Supervised Machine Learning Framework with SHAP Explainability and Real-World Validation”, NMAM Institute of Technology (NMAMIT), Nitte.

Using the API

Send one flow or a list of flows as JSON. Any field you leave out takes the training median.

POST /api/predict
[{"proto": "tcp", "service": "http", "state": "FIN",
  "sttl": 254, "dttl": 252, "sbytes": 1540}]

The response lists the drift probability, tier and recommended action for each flow.
